A sepsis alert for the sea

Hospitals score a patient's vitals every hour and raise an alarm hours before septic shock. This page does the same for a stretch of Florida coast: it reads the last few weeks of Karenia brevis cell counts, water temperature, season and river flow, and asks one question — will this region tip into a fish-killing bloom within four weeks? Then it uses SHAP values to say why, and what that does and does not tell you about what to do.

01
The idea

Borrowing the sepsis playbook

A sepsis early-warning system does not diagnose anything. It watches a trajectory — heart rate, temperature, lactate, white count — and estimates the probability that the patient deteriorates within a horizon. Two design choices make those systems work, and both transfer cleanly: score the trend, not the level (a rising lactate matters more than a high one), and evaluate at a fixed alert budget, because a ward can only chase so many alarms.

Where the analogy strains is worth saying up front, and section 11 does. The short version: patients don't flow into each other, and a hospital knows what to do when the alarm fires. Neither is true of a coastline.

03
The unit of prediction

Defining the patient

A sample is a point. A patient has to be something with a history, so samples are pooled into region × ISO week: nine coastal regions, every week from 1994 to 2023. That gives patient-weeks before the onset filters in section 5.

Nine is a choice, not a fact. K. brevis blooms are coherent along the shore over roughly 50–100 km and Florida's own weekly status reports are organised by county band, so bands of about half a degree of latitude match how the phenomenon and the surveillance actually behave. Finer units (counties) would mostly be empty weeks; coarser ones (whole coast) would average away the onset.

Weeks with no samples are kept, not filled in. A patient whose vitals were not taken this week is still a patient. The count features are simply missing that week, XGBoost learns a default branch for missing values, and a separate feature records how stale the last reading is. Forward-filling would fabricate "stable vitals" that nobody measured.

05
Outcome

What counts as a crash

The label is onset: y = 1 if any sample in the region in weeks t+1…t+4 reaches 100,000 cells/L, evaluated only for weeks where the region's last known reading is below that level. Region-weeks already in bloom are dropped ( of them), exactly as a sepsis model drops patients who are already septic. Predicting that a bloom persists is easy and would inflate every number on this page.

Weeks with no samples in the following four weeks have an unknown outcome and are dropped too (). That leaves region-weeks with onsets: a prevalence of . Every metric below is read against that base rate.

The alternative

"Any exceedance in the horizon", without dropping in-bloom weeks, gives a higher AUROC and a less useful model — it mostly learns that blooms last more than a week. A 50,000 cells/L threshold is reported in section 6 as a sensitivity check.

06
Learning and checking

The model, and how it was tested

The classifier is gradient-boosted trees (XGBoost), the same family behind most deployed sepsis scores, because it handles missing vitals natively, learns interactions like "cooling water after a warm autumn" without being told, and explains cleanly with tree SHAP.

Configuration choices that matter

  • Temporal split, never random. Train 1994–2016, tune on 2017–2019, test once on 2020–2023. Adjacent region-weeks share three of four lag features and usually the same bloom; a random split puts twins on both sides and reports a fantasy.
  • No class re-weighting. scale_pos_weight would lift recall at the cost of calibration, and the alert-rate and lead-time analysis need probabilities that mean what they say. AUPRC is threshold-free anyway.
  • Two monotone constraints. More cells this week and a higher 4-week peak are not allowed to lower the risk. Everything else is left free.
  • Shallow trees, slow learning, early stopping. Depth 4, learning rate 0.03, up to 2,000 rounds, early-stopped on validation log-loss ( trees survived). Stopping on AUPRC instead picks a two-tree model: the ranking is learned by the first split, and every tree after that is buying calibration, not discrimination. The final model is refit on train + validation at that size and touches the test years exactly once.
  • A twin without surveillance features is trained alongside, so you can see how much of the skill is "we sampled more because something was happening".

07
Explanation

SHAP values, globally

A SHAP value answers one question per feature per prediction: how much did this feature's value move this prediction away from the average prediction? The units are the model's log-odds, so for one region-week the values add up exactly: baseline log-odds + sum of all SHAP values = the log-odds the model output. The repo asserts that identity on every test row (largest gap ).

The construction comes from cooperative game theory. Treat each feature as a player, the prediction as the payout, and ask how to divide the payout fairly. Shapley's answer: average each player's marginal contribution over every possible order in which players could join the coalition. Tree SHAP computes that exactly for tree ensembles instead of enumerating orders.

One decision you have to make: what "absent" means

To measure a feature's marginal contribution you must evaluate the model without it, and trees can't do that. Two conventions exist. Path-dependent follows the tree's own training statistics at each split the missing feature would have decided, which is faithful to the trees but lets correlated features (this week's max and the 4-week peak, say) borrow credit from each other along shared paths. Interventional, used here, replaces the missing feature with values drawn from a background sample of training rows, breaking the correlations and answering "what if this feature were set independently of the rest". That is the semantics a waterfall and an intervention argument need, so it is the one to use when the point is to act — at the price of sometimes crediting a feature the model reaches only through a correlated partner.

Dependence: the shape of each effect

Each plot is one column of the beeswarm turned sideways: the feature's value on the x-axis, its SHAP value on the y-axis, and colour from the feature the trees most often interact it with. 08
Explanation, locally

Three patients, three waterfalls

This is the bedside view. Start at the baseline probability (, the average onset rate the model expects with no information), and let each feature push the log-odds up or down until you reach the score. All three are from the held-out years, chosen by rule: the confident true positive with the longest lead; the most confident false alarm; and the quietest July.

The false alarm is the most instructive of the three. A model can only be wrong in the ways its features allow; when a high score does not pan out, the waterfall shows which vital misled it — and often the answer is a surveillance feature, which is the artifact tag earning its keep.

10
From explanation to action

What SHAP can and cannot tell a manager

SHAP explains the model. It says which inputs moved this score, under the model's learned associations. It does not say what would happen to the sea if you changed one of them. The bridge from one to the other is the tag on each feature, and it is a human bridge, not a statistical one.

leverModifiable
  • River discharge — the Caloosahatchee at S-79 is a managed release from Lake Okeechobee. A high discharge SHAP contribution is the only one on this page that points at a valve someone holds.
  • Nutrient loads ride on that flow; the data here carries flow, not nutrients. Treat discharge as a proxy for the real lever.
proxyForecastable, not pullable
  • SST, season, cooling rate — nobody cools the Gulf. But these are forecast weeks ahead, so a high contribution here changes when to watch: it justifies pre-positioning sampling and shellfish testing before the counts move.
artifactSurveillance
  • Samples per week — when this contributes strongly, the model is partly reading the monitoring programme's own reaction. That is a warning label on the score, and an argument for a fixed sampling design so that "how hard we looked" stops correlating with the outcome.
stateThe trajectory
  • Counts and growth — not levers, but the part of the score that tells you how much time you have. A high score built on growth rate is a different situation from one built on a single hot sample.

A what-if on the only lever

The cheapest way to see what the model thinks a lever does is to move it and re-score. Below, the 30-day discharge features are reduced by 30% for every week of the episode and the model is asked again. Everything else — including the counts that discharge might, in reality, have influenced — is held fixed, which is precisely why this is a model exercise and not an environmental impact statement.

Why this is not a causal estimate

Discharge co-varies with the wet season, with rainfall, with wind and with the very temperature signals the model also reads. XGBoost learned a conditional association, not a mechanism; there is no identification strategy here — no instrument, no natural experiment, no dose-response from managed releases. The what-if measures the model's sensitivity, which is a hypothesis generator. The experiment that would test it belongs to the Army Corps and the South Florida Water Management District, not to this page.

How a score like this would actually be used

  1. Tiered alerts at a fixed budget. Pick the alert rate the monitoring programme can act on (the 10% row in section 6) and let the threshold follow from it, exactly as a ward sets its alarm rate. Precision and recall at that budget are the numbers to publish, not AUROC.
  2. Read the waterfall before acting. An alert driven by growth and cooling water means "sample here now, warn shellfish harvesters, pre-stage respiratory-irritation advisories". An alert driven by sample count means "you are looking at your own footprint; verify before escalating".
  3. Route lever contributions to the lever's owner. A discharge-driven alert in Lee–Collier is a memo to the people who schedule releases, with the what-if attached as a question, not a finding.
  4. Fix the surveillance design. The single most useful intervention this analysis suggests is to the data, not the ecosystem: fixed-station weekly sampling would remove the artifact channel and make every other SHAP value more trustworthy.
  5. Close the loop. Every alert and its outcome go back into the training set. A sepsis model that is never retrained drifts; so will this.
11
Honesty

Where the analogy breaks, and other limits

  • Patients are independent; regions are not. Blooms advect along the coast. Sarasota's onset is often Lee–Collier's bloom moving north, which the region-wise model treats as two events. Neighbouring-region features would be the obvious next step.
  • Sepsis has a treatment; a bloom has a response. Antibiotics within the hour change the outcome. Nothing a manager can do in four weeks stops a bloom that has begun; the actions are protective (closures, advisories) and preparatory (sampling), which is why lead time matters more here than in the clinic.
  • Sepsis labels are adjudicated; bloom labels depend on where the bottle was dipped. An onset that happened between sampling sites is invisible. The 'unknown outcome' filter removes the worst of this and cannot remove all of it.
  • Surveillance is endogenous. Sampling intensifies when blooms are suspected. The ablation in section 6 bounds the effect; it cannot eliminate it.
  • Discharge is flow, not nutrients; temperature is a 0.25° box average, not the water a cell lives in; wind and upwelling, which are physically important for K. brevis transport, are not in this version.
  • Interventional SHAP breaks correlations by construction, so it can assign credit to a feature the model only reaches through a partner. The dependence plots colour that partner for exactly this reason.
  • This is a demonstration of method on a single public archive, not an operational forecast. FWC and NOAA run real ones.

Repeat it

Reproduce it

The pipeline is a folder of small scripts, each writing a cached file the next one reads. On a laptop the whole arc — download, features, two models, SHAP, this page — runs in under an hour, most of it waiting on the SST server.

uv venv --python 3.12 .venv && uv pip install -r requirements.txt
cd src
../.venv/bin/python -m hab.fetch_fwc            # 196k samples, six ArcGIS layers, paginated
../.venv/bin/python -m hab.fetch_env            # OISST per region box + USGS daily discharge
../.venv/bin/python -m hab.build_features --self-test   # the leakage test
../.venv/bin/python -m hab.build_features       # region-week table, vitals, onset label
../.venv/bin/python -m hab.train                # full + no-surveillance models, metrics.json
../.venv/bin/python -m hab.explain              # interventional TreeExplainer, additivity check
../.venv/bin/python -m hab.whatif               # discharge −30% re-score
../.venv/bin/python -m hab.export_site_data     # site_data.json
../.venv/bin/python -m hab.build_site           # this page
